Native recovery safety review (2026-09-14; read-only, not a reboot test):
Exact installed Linux 6.18.43 source:

The installed MT7921 patch only keeps D0 on remove; it does not add a
pre-probe reset. Native mt7921 PCI probe enables bus mastering before its
checked WFSYS reset, then disables/resets DMA before native queue allocation.

Driver-core dma_configure runs before native probe. PCI default-domain
ownership and AMD attachment therefore precede pci_set_master. np currently
reports singleton group19 DMA-FQ, translated default domain and IRQ remapping;
reserved regions are MSI and 0xfd00000000..0xffffffffff, not ordinary RAM.
This supports only conditional post-IOMMU-initialization containment: a fresh
empty translated domain could prevent ordinary stale untranslated DMA.
Default-domain ownership is not proof of emptiness.

Automatic ordinary reboot remains BLOCKED:
- AMD early_enable_iommu explicitly disables translation while configuring it;
  BME containment across firmware and that interval has not been proved.
- Applicable ATS/device-cache state and completed invalidation are unverified.
- Current interrupt remapping does not prove continuous reboot-time isolation;
  neither IOMMU translation nor healthy post-boot status proves RF reset.
